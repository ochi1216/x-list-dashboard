# 実装時の決定記録(3人のPM協議・多数決。仕様v11の未決事項22点)

PM-A=音声・UX / PM-B=費用・運用・安全 / PM-C=データ品質・評価。公開リポジトリのため、秘密・関心プロファイル本文・個人情報はここに書かない。

| # | 決定 |
|---|---|
| 1 | バックエンドは `backend/` に置く。Pagesは許可リスト方式(index.html・index_beta.html・index_prev.htmlだけ公開)に絞り、公開前後でHTTP200を確認。原本は `backend/legacy/` に退避済み。 |
| 2 | 採点は2.5で今すぐ暫定開始(`scored_model`記録・画面は小さな「暫定」チップ)。閾値は自動算出せず「≥4＋聴く枠(分)」。暫定期間は枠を半分(10分)。閾値の再計算はモデル/プロンプト/プロファイルの版が変わった時だけ(`threshold_version`で固定)。 |
| 3 | 採点は要約と別呼び出し。再採点(閾値T-1とT)は `rescore` が有効なモデルのみ(2.5は温度0で決定的なので無効)。読み下し(speech)は採点に混ぜず、聴くが確定した投稿だけ別呼び出し。 |
| 4 | 採点入力: 画像ありは本文＋要約＋画像枚数、本文のみは本文だけ。投稿者名は入れない。evidenceは入力からの引用必須(無ければ最大3)。画像は再投入しない。 |
| 5 | 関心プロファイル(≤600字)はDBのみ。W4はAI全般に広げ、私生活(P1〜P3,P5)は載せない。採点に`interest`を保存。 |
| 6 | 管理認証: Vaultに署名鍵、DBにはPBKDF2ハッシュのみ。一回限り・7日有効のセットアップコードで初回のパスフレーズを自分で設定。トークン30日(使うたび延長)。上限・通知・認証モード変更は再入力必須。 |
| 7 | 共有シークレットは呼び出し元別(cron=全関数、Windows=summarize-x-postのみ)。新関数は最初から必須。summarize-x-postはlog→enforce(log中はpost_url指定を拒否・limit上限60)。 |
| 8 | バッチ=`fetched_at`の空き90分未満で連なる投稿(fetch_runs非依存)。最後のINSERTから20分静止で取得完了。未採点があっても最初の投稿から4時間で確定。`tier_scope_from`より前は区分・自動既読の対象外。 |
| 9 | 聴く枠: 日は02:00 JST起点、朝=日枠×60%、夕=日枠−朝の実使用(朝が無い日は夕が100%)、同枠の複数バッチは残りを共有。見積は文字数÷(6.5文字/秒×速度1.2)。 |
| 10 | 聴く→24時間で流す(その後72時間)。流す・保留の72時間後の自動既読化は `auto_expire_enabled`(暫定中false)・1回上限400件。`tier_initial`を不変保存、`read_via`を記録。 |
| 11 | 手動昇格/降格は管理API経由。端末キューは操作ID付き(冪等)。画面は即時反映し、ログイン画面で止めない。 |
| 12 | 通知: ntfyトピックはサーバーが生成してVaultへ。設定画面に表示+テスト通知。本文は事象ラベルと件数のみ。errorは6時間、warnは24時間に1回へ集約。healthchecks.ioのURL登録は越智さん作業。 |
| 13 | 費用ガード: 月4,000円(80%警告/100%追加処理停止/130%全停止)、日次400円、1時間600呼び出し、全呼び出しにmaxOutputTokens必須。TI系は1日500回(Gemini呼び出し単位)。全停止スイッチ`kill_switch`。 |
| 14 | 週次レポートは日曜18:45 UTC、週の区切りは02:00 JST。提案LLMは同一モデル・プロファイル版で連続4週たまるまで休止。 |
| 15 | 今日の要点は区分確定の直後に生成(新規score3以上5件以上・最短6時間)。数値・固有名・日付が引用カードに無い文は削除、全滅なら「生成できません」。今週の流れは「蓄積中 n/7」。旧digest_summariesは新UI公開まで旧形式で維持。 |

| 20 | ラベル60件は20件×3回、投稿者名は隠し基準は「聴く価値」、区分は告知/参照のみ/意見・感想/その他。抽出は一様ランダム枠を含め全投稿の抽出確率>0。 |
| 21 | キャップ: 重複→1(採点前にコード判定)、本文も画像も無い→1、告知→1(ただし生スコア4以上と矛盾なら3に留めて記録)、参照のみ→最大3、evidence無しで4以上→3、指示文混入→2。意見・感想→3は`cap_opinion`(初期false=記録のみ)。全キャップで`score_raw`と`cap_reason`保存。 |
